## 1. 阶段 7 技能管理总结

### 1.1 已完成（D1 + D2，已合 master）

上线范围是「底座 + 最高性价比校验」，只做了两项：

- **D1 对齐 Agent Skills 规范**
  - 4 个 `apps/agent/skills/*.skill.md` 改为 **YAML frontmatter**：
    `name / description / version / tools / scenarios / enabled`
  - 新增 `harness/skills.frontmatter.ts` 的 `parseSkill(content, filename) → { meta, body }`
  - `body` 会剥离 frontmatter（避免元数据漏进 system prompt）
  - 无 frontmatter / YAML 解析失败 → **回退旧正则格式**，行为与改造前一致
- **D2 技能 ↔ 工具绑定校验（fail-fast）**
  - `SkillsLoader` 注入 `ToolRegistry`；`loadAll()` 从构造函数挪到 `onModuleInit`
    （Nest 先填注册表，避免读到空表）
  - 技能声明的工具未注册 → **隔离该技能**，非生产启动 `throw`、生产仅 `logger.error`
  - `enabled: false` 直接跳过
  - 数据修正：`template-market.skill.md` 摘除未注册的 `template_publish`
- **验证**：`test/skills-loader.spec.ts` 7 例；2026-10-19 全量 `vitest` **1072 全绿**（33 文件），agent `tsc` 干净。

### 1.2 D3 渐进式加载（待做）

**现状**：`subgraph.factory.ts` 每轮把 `SkillsLoader.getAllMeta()` 的**全部技能元数据**注入 system prompt
（当前 4 个技能，约 500 token）；正文仍按需 `loadFull()`。

**目标**：按本轮路由到的领域，只注入相关技能的元数据；未命中时回退「注入全部」。

**方案**
1. 在技能 frontmatter 里补充领域标签（或复用 `scenarios`）。
2. 路由完成后，按 `route.domain` 过滤 `getAllMeta()`；过滤结果为空 → 全部注入。
3. 正文加载不变（仍按 `loadFull(label)`）。
4. 单测：命中领域只含相关技能；未知领域回退全部；注入内容不含 frontmatter。

**验收**：技能增至 10+ 后，system prompt 的技能元数据 token 不随总数线性增长；
路由不变时行为与现在一致。

**为什么现在不做**：只有 4 个技能，节省的 token 可忽略；同时会增加「路由领域 → 技能」映射的耦合。

### 1.3 D4 技能级权限（待做）

**现状**：D2 只校验「技能声明的工具**存在**」；阶段 6 的策略引擎是**全局**规则
（跨租户、批量阈值、删除确认），不区分「哪个技能在调用」。

**目标**：技能只能调用自己声明过的工具集合，越界即拒绝（最小权限）。

**方案**
1. frontmatter 增加 `permissions.allowedTools` 与可选 `maxRisk`。
2. 在 `ToolGateway` / 策略钩子中传入当前技能身份，与阶段 6 的内置规则**取最严者**：
   `deny > requireConfirm > warn > allow`。
3. 与 D2 的关系：D2 在启动时保证「声明的工具存在」，D4 在运行时保证「只能调声明过的工具」。
4. 单测：越界工具被拒；声明内放行；未声明 `permissions` 的技能按现状（不额外限制）。

**验收**：某技能尝试调用未声明工具 → 被拒并写审计；正常调用不受影响。

**为什么现在不做**：现阶段技能与工具基本一一对应、技能文件都在仓库内由开发者维护，越权风险低；
等支持外部导入技能或多人维护时再上。

### 1.4 D5 技能版本化 + eval 门禁（待做）

**现状**：frontmatter 已有 `version` 字段，但**没有被使用**；阶段 2 的 eval（11 例）覆盖主流程，
但没有「按技能」做改动门禁。

**目标**：技能改动可追溯、可回归、可回滚。

**方案**
1. 加载时记录技能 `{name, version}` 到启动日志 / `session.metadata`，便于排障定位版本。
2. 建立「技能 → eval 用例」映射；修改某 `.skill.md` 时自动跑对应用例。
3. CI 中增加技能变更检查：回归不通过不允许合并；技能版本号未变但内容变化时告警。
4. 单测 / CI：版本记录、映射缺失时的兜底（跑全量 eval）。

**验收**：改 skill 后 eval 回归自动执行；线上问题能凭版本号定位；回滚技能只需回滚文件版本。

**为什么现在不做**：技能是仓库内文件，改动本身走代码评审；等支持热更新 / 技能市场 / 远程分发时，
独立版本与回归门禁才有必要。
