## 二、流程引擎

### 1. 条件求值修复
- **根因**：旧 `evaluateConditionNode` 读 `node.config.branches`，实际条件存在 **edges** 上
- **修复**：新增 `evaluateConditionEdges`，直接遍历条件节点的出边，按 `condition` + `_isDefault` 求值

### 2. 自动穿越网关节点
- **根因**：`approveTask` 审批通过后只走一步到下一节点，遇条件/并行/抄送等无任务节点就停住
- **修复**：新增 `advanceThroughGateways`，自动穿越 `condition/parallel/join/cc/auto-task` 直到遇审批节点或结束。`startProcess` 和 `approveTask` 均调用

### 3. 表达式兼容
- **根因**：旧表达式是 `${field > 5000}`，引擎 Lexer 不认识 `$` `{` `}`，抛异常被静默吞掉
- **修复**：引擎侧用正则 `/\$\{(\w+)\}/g` 全局剥离 `${}` → 纯变量名；设计器侧 `buildCondition` 改为生成纯格式（如 `field > 5000`）

### 4. 会签评估过时数据修复
- **根因**：`approveTask` 中 `updateMany` 更新 DB 后，内存中 `instance.tasks` 仍是旧状态，`CountersignEvaluator` 读到过期数据返 `pending`
- **修复**：`updateMany` 后重新 `findMany` 该节点任务，用最新状态评估

## 八、关键技术决策

| 问题 | 决策 |
|------|------|
| 条件数据存哪里 | 存在 **edges**（非 node.config） |
| 表达式格式 | 纯 DSL（`field > 5000`），引擎侧兼容旧 `${}` 格式 |
| 工作流触发方式 | 只能由表单填写提交触发，移除手动发起入口 |
| 流程→表单关系 | 一对一，后来绑定的流程优先，自动解绑旧流程 |
| 发布后操作 | 发布按钮变为"撤销发布"，取消"发起流程"按钮 |
| DB 字段 | ProcessDefinition 新增 `publishedAt` |
